## 1. 路线图定位

- **与 PRD 的关系**：PRD 回答「做什么、为什么」，本 Roadmap 回答「先做什么、何时做」；
- **优先级口径**：P0 = 已交付；P1 = 下一迭代；P2 = 远期规划；
- **排序原则**：用户价值 × 实现成本 × 架构契合度；优先落地复用现有 `SwitchService` / `PresetRepository` / 目标注册表的小步增量；
- **非目标不变**：不做云端同步、不修改 CLI 内部行为、不做对话/调试客户端（对齐 PRD §1.4）。

## 3. 核心洞察（为什么是这个顺序）

1. **双工具聚合体验缺失**：主力用户同时使用 Claude Code 与 Codex CLI，但当前以「工具」为维度管理预设，缺少「一次切换全家生效」的路径——这是当前产品最大的体验盲点；
2. **上手资产化不足**：新用户不知道「Base URL / 模型名填什么」，老用户缺少可复用的模板与分享手段，漏斗在「创建第一个预设」处最陡；
3. **安全信任最后一公里**：API Key 仍明文存于 `~/.aiswitch/presets.json`（PRD §7.3 已识别），是影响长期使用与口碑的关键项；
4. **高频操作的效率**：托盘切换需「两步 + 鼠标」，高频用户需要快捷键盲操作。

## 5. 依赖与风险

| 编号 | 依赖 / 风险                         | 缓解策略                                                  |
| ---- | ----------------------------------- | --------------------------------------------------------- |
| 5.1  | 钥匙串在 Windows / Linux 平台差异   | 抽象统一 keyring 接口，各平台适配；失败降级回本地加密文件 |
| 5.2  | 项目级配置与全局配置优先级易混淆    | 以「项目 > 全局」为唯一规则，UI 明确标注作用域            |
| 5.3  | 本地模型端点多样（兼容层 / 直连）   | 模板内置常见地址，连通性测试沿用现有探测规则              |
| 5.4  | CLI 二进制分发与 GUI 版本一致性问题 | 随发布流水线一并产各平台二进制，版本号统一                |

## 6. 落地节奏建议

1. **下一迭代（P1）**：US-17 组合预设 → US-20 全局快捷键 → US-18 钥匙串（三条主线各一，均基于现有架构小步落地）；
2. **紧接着**：US-19 模板库 + 本地模型，与 US-12 导入导出打通，打开上手漏斗；
3. **随后**：US-09 CLI + US-23 Shell 集成、US-21 项目级配置、US-22 切换历史/漂移检测；
4. **远期**：自动更新、更多目标工具、诊断包、成本估算。

> 任何条目进入开发前，须先在 `docs/PRD.md` 补齐用户故事与验收标准，再按 `docs/CODING_STANDARDS.md` 落地并同步测试。
